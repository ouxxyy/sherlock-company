# 证据合同

## 四种状态

| 状态 | 何时使用 | 可以怎么说 |
| --- | --- | --- |
| `verified` | 原始材料可访问，主体、时间和适用范围一致 | “已确认……” |
| `signal` | 有来源的线索，但缺原文、独立印证或目标团队关联 | “有线索指向……，还不能证明……” |
| `conflict` | 可用材料得出不同方向，且无法消解 | “目前说法矛盾：A……，B……” |
| `unknown` | 未取得能回答该问题的材料 | “还不知道……” |

`blocked` 和 `not_found` 是检索状态，不是事实结论。页面被拦截、需登录、超时或返回 0 条时，只记录覆盖缺口。

`verified` 来源的访问状态必须是 `accessed` 或 `local`。只有搜索摘要、链接被拦截、需登录、未发现或调用失败时，无论内容多么“像真的”都不能作为已证实事实的唯一依据。

## 每条记录的最小字段

- `claim`：只写一个可验证断言。
- `status`：四种状态之一。
- `source_id`：指向来源登记表。
- `subject`：品牌、法律主体、城市、业务线或团队。
- `event_date` / `retrieved_at`：事件时间与取证时间分开。
- `supports`：它能证明什么。
- `limits`：它不能证明什么。
- `decision_impact`：对用户关切的影响；无影响就不硬塞。

## 来源强度与适用范围

1. 用户的 Offer、合同草案、公司制度原文：适合核对本次机会的承诺和条款。
2. 政府、法院、交易所、企业公示、企查查官方数据：适合主体、登记、公开风险和法律事项。
3. 企业官网、招聘页、HR 回复：证明官方如何表述，不证明实际兑现。
4. 有署名和语境的一手员工材料：只适用于对应时间、城市、职能和团队。
5. 匿名帖、评价截图、聚合页：默认为线索，不由数量直接推断发生率。
6. 搜索摘要、AI 摘要：仅用于找原文。

## 结论守门

- 先证明主体，再查其它事。
- 一条证据不跨主体、城市、团队或时间外推。
- 负面材料分为“指控存在”、“争议进行中”、“结果已确认”。
- 每个关键结论检查至少一个合理的替代解释或反证。
- 未知项写明“为什么影响决定”和“去哪里核实”，不只写“信息不足”。
