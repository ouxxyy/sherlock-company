# HTML 报告设计合同

## 信息架构

默认使用多张连续卡片，不把整份调查压成一张评分卡：

1. **封面卡**：公司、岗位、城市、调查日期、范围，保留侦探 IP。
2. **当前决定卡**：一句话状态 + 为什么 + 立即做什么。
3. **主体链卡**：品牌、总部/母公司、招聘、合同、发薪/个税、社保/公积金主体分开标状态。
4. **证据分盒**：已证实、有线索、说法冲突、仍未知分开展示。
5. **关切卡组**：每个用户问题一张卡，固定写已知、未知、影响、下一步。
6. **员工体验卡**：当前覆盖、能说什么、不能说什么、最便宜的补证路线。
7. **Offer 前核实卡**：按阶段分组，含可复制问法、应取得的材料、需警惕的回复。
8. **材料和来源卡**：已收到/待补材料、隐私复核状态、来源、日期、访问状态、适用范围和局限。

证据细节可用原生 `<details>` 收纳，关键结论不得藏在翻卡或悬浮交互里。

## 文案

使用“小夏的结论”、“已查到”、“还不知道”、“接受前要到什么”这类自然中文。不使用“恭喜抽中”、“验明正身”、“终极真相”、“一锤定音”等娱乐化断言。IP 只负责引导阅读，不应改变证据强度。

卡片标题优先使用用户问的原话，比如“奖金到底怎么发？”，而非“薪酬信号综合裁决”。

- 界面标题、分区标签和结论默认使用中文，不添加 `INTERACTIVE`、`CHEAT SHEET`、`STARS`、`SERIES` 等装饰性英文。
- 法律实体英文名、来源原题、网址和产品正式名称可以保留。行业缩写首次出现时优先写成“职位说明（JD）”这类中文说明；正文优先使用“职位说明”“录用通知”“招聘人员”。
- 直接写判断和依据，不用“不是……而是……”“不猜……只……”等翻案式模板。少用破折号制造停顿，不用英文全大写制造视觉层级。

## 视觉模板

- `scripts/render_report.py` 是生成入口，默认嵌入 `assets/report-v2.css`。修改独立样例 HTML 不会改变 Skill 产物。
- 采用证据卷宗式浅色页面、单一珊瑚橙品牌强调色和语义状态色。封面、结论、证据、关切、核实清单与来源使用不同布局层级，不堆叠等宽彩色卡片。
- 关键结论直接显示。来源细节可使用原生 `<details>`，不使用依赖 JavaScript 的翻卡、弹窗或复制按钮。

## 技术约束

- 产出单文件离线 HTML，不依赖 CDN、外链字体或 JavaScript。
- 输入文字全部 HTML 转义；外链只允许 `http` / `https`。
- 所有外链使用 `target="_blank" rel="noopener noreferrer"`。
- 侦探图像嵌入 data URI，保持离线可用。
- 375px 宽屏无横向滚动；重要信息不依赖 hover。
- 考虑打印：去除背景纹理和阴影，避免卡片中间断页。
- 展示数量只能是可复算的记录数，不显示无定义的完整度百分比。
