# 用户材料核对

## 隐私边界

请用户先遮盖身份证号、手机号、家庭住址、银行卡、签名、聊天对方的私人信息和无关人名。只对本次求职判断所需内容做本地分析。未获用户明确授权，不把截图、Offer 或聊天内容提交给公开搜索、第三方模型或企业数据服务。

## 核对顺序

1. **主体**：Offer 抬头、合同甲方、公章、发薪、社保、公积金和个税申报主体是否一致。
2. **岗位与地点**：职级、直接汇报人、城市、办公方式、调动和出差条款。
3. **固定收入**：月薪、计薪月数、发薪日、试用期折算和工资构成。
4. **变动收入**：目标奖金还是保底奖金、公式、基数、系数、发放月份、入离职折算和公司裁量权。
5. **试用期**：时长、录用条件、指标、权重、考核人、反馈频率、不通过标准。
6. **工作时间**：制度、考勤、加班审批、调休、加班费与目标团队的实际节奏分开。
7. **失效条件**：业务调整、组织变更、离职、违纪、绩效或未满周期时的处理。

## 表达约束

- “HR 说过”记为沟通记录；“Offer 写明”记为书面承诺；“合同/制度写明”再记为条款事实。
- 文本一致不等于实际兑现；实际兑现需要过往发放、考勤或员工体验方面的证据。
- 发现文本冲突时，并列原文、标出位置，不自行选择对用户更有利的版本。
