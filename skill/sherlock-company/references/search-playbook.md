# 公司评价搜索与核验

开始联网调查时读取。目标是找到能回答本次机会关切的材料，而不是堆积公司新闻或负面帖子。

## 按关切组织检索

建立品牌、法律主体、历史名称、产品/业务线别名表；别名关系须有依据。每个关切写出目标城市、岗位、团队和时间范围，缺失项保持未知。合同主体未知不妨碍查已确认品牌的线索，但不得把品牌线索当成本次签约实体的事实。

按截止日期与重要性记录本次预算，分别为结果发现和原文/评论核验留出容量。优先处理会改变决定的关切，不在工商信息上耗尽员工体验预算。

| 关切 | 可组合的查询词 | 要找的实际行为 |
| --- | --- | --- |
| 工作强度 | 加班、下班、双休、周末、值班、调休 | 最近工作日/周末频率、上线期与平时差异 |
| 薪酬兑现 | 年终奖、绩效、奖金、发薪、调薪 | 发放年份、条件、实际兑现与承诺差异 |
| 管理与稳定 | 试用期、转正、绩效、裁员、项目撤销、离职 | 目标变更、评定过程、具体事件与结果 |
| 机会匹配 | 岗位名称、业务线、面经、入职体验 | 面试经历和入职后经历分开 |

先试“品牌 + 城市/岗位 + 关切”，再按缺口加站点或别名。窄查询无结果时逐步去掉岗位、城市或时间条件；扩大范围后的材料明确标成旁证。不要只搜“避雷”“垃圾”等负面词；补中性问法和合理反证，例如“下班时间”“双休”“奖金兑现”。没有正面证据不强凑平衡。

示例（只选与关切相关的组合，不全排列）：

- `4399 厦门 测试 下班`
- `site:nowcoder.com/discuss 4399 工作体验`
- `site:maimai.cn 四三九九 年终奖`
- 用已发现原文中的标题、业务线或具体事件继续追出处，不猜文章 ID。

优先检索近期材料；例如先看近一年，缺口较大时扩到历史。年份只是过滤线索，必须读原文核对事件日期。发布时间、更新日期、取证日期分开；网页推荐区的新日期不能用于正文。组织调整前后的体验分开描述。

## 信息源选择

| 渠道 | 适合补什么 | 证据局限 |
| --- | --- | --- |
| 脉脉公司点评、职言、讨论与评论 | 工作强度、奖金、管理、组织变化 | 登录态可能增加可见范围；匿名、认证标签、点赞均不保证事实真实 |
| 牛客讨论/评论 | 校招、面试、录用比较及部分入职体验 | 求职者提问不是亲历；内推广告不是独立评价；校招不能代表社招 |
| 看准的公司评价/面试栏目 | 员工体验或面试过程 | 栏目、样本时间、地区、岗位需要分别核对；评分不等于公司事实 |
| 知乎、V2EX、公开个人长文 | 有上下文的具体经历、事件追溯 | 转述、推广和旧文须识别；只取已读原文 |
| 招聘官网、官方招聘账号、职位页 | 公开承诺、岗位和工作地 | 不证明承诺兑现，多个内推转发可同源 |
| 政府/司法/交易所、可靠媒体、企查查 | 主体、经营与争议的可核对记录 | 不是目标团队体验，争议与终局结果分开 |
| 海外业务相关的 Glassdoor / Indeed / Blind | 对应国家和办公室的体验 | 只有目标范围匹配时才选，不外推到中国团队 |

这些是候选渠道，不是已访问清单。依目标选择适用渠道，记录实际动作；不能沿用旧案的拦截状态。小红书仅处理用户提供或历史本地材料，不联网采集。

公开搜索工具用来发现直链；站点限定搜索与站内搜索互补。公开抓取拿不到正文而浏览器可用时，转浏览器读取。涉及登录态或用户明确要求 Tabbit 时读取 [authenticated-reviews.md](authenticated-reviews.md)。不把浏览器登录信息交给公共抓取服务。

## 从“搜到帖子”到“有用证据”

1. 打开原文，区分正文、评论、相关推荐、平台模板；只登记实际读到的范围。摘要命中不计为原文命中。
2. 判断材料是亲历自述、面试体验、提问、招聘推广、新闻转述还是无出处汇编。域名为脉脉/牛客不代表来自该公司员工；“我在职”只记自述身份。
3. 提取与关切相关的具体行为、事件时间、城市、岗位和团队；看得到才填，IP 属地不当工作地，认证不当真实性背书。
4. 在可用范围内读取相关评论、楼主补充和反驳，保留上下文。未展开、只看热门、分页不完整或平台过滤过评论须明写，即使页面显示“没有更多了”也不能说“全部评论一致”。平台 AI 助手的总结不当作独立员工样本，须追其原始来源。
5. 用规范 URL、帖子 ID、相同段落/事件与转引关系归并同源材料。移动版、桌面版和多站转载不算独立证据；同帖多个评论也不能默认独立。
6. 对关键主张找原始依据与替代解释。不同城市、年份、团队的相反经历先分层，不强行归为同范围冲突或全公司结论。

公开帖和登录态帖都不能保证“真实”。可确认的是某条记录存在；体验事实的可信程度还依赖身份依据、时间、范围、细节和独立印证。见 [evidence-contract.md](evidence-contract.md)。

## 留痕与停止

用案件目录的 `search-log.md` 或现有检索日志逐次记录：关切、查询/入口、渠道、公开/登录态、时间、实际结果、原文/评论覆盖、来源 ID、下一步或停止理由。检索结果用 `accessed / partial / login_required / blocked / failed / not_found / not_attempted`；`partial`、`not_attempted` 是日志字段，不直接填入报告来源的 `access_status`。

`not_attempted` 写明未尝试的原因（预算、工具不可用、范围不相关），不能改成 `blocked`。只有真实执行的搜索才能写 `not_found`。登录首页、搜索结果卡片和正文/评论的访问状态分别记录。

结束时逐项列出“关切 → 可用材料 → 时间/团队相关度 → 缺口 → 补证动作”。检索预算耗尽、只剩重复材料或渠道阻塞时交付阶段报告；它们都不等于调查完整或体验已核实。报告 `coverage_gaps` 和 `employee_experience` 必须反映这些缺口。记录候选条目数、已读原文数和同源去重结果有助于复核，但不用命中数量计算真实性或完整度分数。
