# 登录态公司评价：Tabbit 路线

当用户要求登录后的脉脉评价，或公开检索缺少关键体验且有可用浏览器时读取。本流程使用当前用户有权访问的页面，只读搜索和阅读，不发帖、不点赞、不私信、不申请职位。

## 连接与真实访问检查

优先按用户指定的 Tabbit 浏览器执行。环境中有 `tabbit` 技能时先读该技能，按其稳定 launcher、任务归属、请求回执和 finish 规则操作。不要求安装额外爬虫；Tabbit 不可用时记录工具缺口并继续公开来源或用户材料。

macOS 可用的启动方式（具体 CLI 行为以安装的 Tabbit 技能为准）：

```bash
"$HOME/.local/bin/tabbit-cli" create --task "公司评价调查"
```

检查实际页面，不根据标签页列表或旧案例推断登录状态。已有相关用户标签页按返回的 tab ID 获取；否则打开 `https://maimai.cn/`，观察当前搜索框与导航，再搜索公司名。不要硬编码未经观察的公司 ID、搜索接口、选择器或 App 私有 API。

若出现登录/验证码：登记 `login_required`，由用户在浏览器完成登录；不读取 Cookie、令牌、密码或短信，不代填验证码。报告 `AUTHENTICATION_REQUIRED` 并保留页面。继续不依赖登录的工作；用户回复已登录后重新观察实际页面，不能把回复本身当访问成功。

## 搜索与阅读

- 已登录也要分别验证搜索结果、公司点评详情和评论能否读取。有首页不代表可读点评；手机 App 可见不代表网页可见。
- 从已观察到的搜索入口搜品牌/别名，再按页面实际提供的栏目进入公司、点评、职言或讨论。没有独立“公司点评”入口时记录实际栏目，不能声称已检索该栏目。
- 若有可用筛选，结合城市、职能、时间和最新排序查关键关切；默认热门排序只能代表本次热门样本。站内无结果再调整别名或减少条件，不猜测隐私接口。
- 打开相关帖子/点评详情，按 [search-playbook.md](search-playbook.md) 识别材料类型、正文与评论、时间和独立性。每次只取决策所需的有限内容，不扫描账号关系或个人主页。
- 搜索框可能只显示联想结果；按页面实际的“查看全部搜索结果”等入口提交，并核对结果标题/查询是否更新。进入详情可能新开标签页，先检查任务拥有的页面再切换。
- 加载提示可能是列表底部的持续加载器；以目标结果条目出现、查询标题更新为就绪依据，不要求所有“加载中”消失。
- 分页/滚动必须观察新条目或停止提示。记录已读页数/条目和未展开部分；遇到 App-only、付费、访问拒绝或限流就记录缺口。遵守站点限制，不切账号、伪装身份或绕过验证。

有搜索结果卡片但详情打不开时，把卡片内容保留为 `signal`，来源注明“仅卡片可读”；体验正文没取得时不得记为已覆盖目标团队。匿名或自述员工的原文已读也默认 `signal`，除非对应主张有足够独立依据。

## 留存与交付

记录来源平台、可复访 URL 或页面定位说明、取证时间、正文/评论覆盖、作者身份依据（自述/页面标识/未知）、事件时间、城市、岗位、团队及限制。登录不降低证据标准。

登录态原文、截图和用户名只在确有必要且用户允许时本地留存，先脱敏；不把登录态全文、账号资料、Cookie、二维码或验证码提交到公共仓库或第三方搜索。公开审计报告只保留必要的非敏感方法、公开链接和访问结果。

读取所有需要的回执/资源后用同一任务名 `finish` 释放所有权并保留登录页及用户标签页；不使用会关闭全部标签页的 `--discard`。体验仍不足时转 [employee-experience.md](employee-experience.md)，不要把“登录后应该能看到”写成已完成验证。
