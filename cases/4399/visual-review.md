## Executive Summary（总体复核综述）

本版 4399 离线侦探档案（Sherlock Dossier）建立了完整的侦探尽调视觉架构：涵盖核心裁决（The Verdict Hero）、五维深度体检（Dimension Scan）、主体防混淆矩阵（Entity Matrix）、证据链溯源账本（Evidence Ledger）、竞争假设辩证（Hypothesis Dialectics）以及实战面试武器库（Interview Weaponry）。信息密度极高，板块脉络清晰。

然而，以**乔布斯级苛刻审美**及**严肃商业尽调标准**审视，当前设计存在两项致命的事实定性越界（P0 级）、多处排版对比度与可读性缺陷（P1 级），以及典型的暗黑模式下“消防栓式过度警示”的美学噪点（P2 级）：

1. **事实定性严重越界（P0 级）**：移动端直接断言「广州办公但合同签厦门或外包极其常见！」，将尚无一手统计证据的推测/防范提醒，硬生生写成了已普遍发生的既定事实；同时，广州拿地在出图时存在超前断言，现虽经政府源核实（E17），但截图中缺乏“重资产资本开支非稳定性支柱”的中立定位注记，易误导为经营稳健背书。
2. **警示层级喧宾夺主（P1 级）**：高饱和亮红/深红警示卡片权重过高，打破了 3.5★ 评级的中立平衡感，让案卷呈现出廉价的“系统故障报警”视觉效果，违背了严肃调查档案的克制冷峻气质。
3. **网格断层与移动端挤压（P1 级）**：桌面端主体三列卡片高度严重不齐，右侧留下大面积尴尬空洞；移动端五维评级胶囊标签在 390px 边缘紧绷，缺乏安全留白，在小屏设备上极易发生文字折行与溢出。

## 零、事实与推测边界审查（核心红线 · P0 级）

### 0.1 合同主体混同被煽动性暗示为“已发生普遍事实”【严重违规】
- **违规位置**：
  - **移动端**主体卡片底部的警报卡（`sherlock-dossier-4399-mobile.png` 第 3 屏）：
    > `⚠️ 签约主体未知警报`  
    > `广州办公但合同签厦门或外包极其常见！面试必须明确签约单位全称与社保城市！`
  - **桌面端**主体矩阵右侧警示卡：
    > `【求职防坑必读】研发与办公在广州，但官网招聘与签约的主体可能为厦门或第三方外包。劳动关系归属直接决定社保落户与劳动纠纷管辖法院，必须书面明确！`
- **事实与证据溯源**：
  - 在 `04-证据账本.md` 中，全案一手员工体验证据为 **0 条**。
  - 没有任何公开裁决文书、劳动争议裁判或可信一手证据证实 4399 存在“广州办公但签外包或签厦门”的既成事实。
  - 在文字报告 `report.md` 中，该项仅仅被定性为求职者在面试时需主动查验的**防坑核实问题（面试第一问）**，属于防御性假设，而非已查证问题。
- **视觉定性问题**：
  - 移动端文案使用感叹号并断言**「极其常见！」**，这是极其严重的“以主观臆断代替事实”的越界行为！它将行业普遍风险或求职防御假设，擅自放大为该企业已经普遍发生的用工劣迹，严重违背“证据不足不得推定已发生”的铁律。
- **修订方案（Must Fix）**：
  - 必须彻底删除「极其常见！」等主观推断词与感叹号。
  - 修改为客观中立的防御提示：
    > `⚠️ 签约主体核验提示`  
    > `广州研发属全资子公司，但公开招聘多以厦门母公司名义发布。求职者须在面试及 Offer 阶段书面核实签约法人全称与社保缴纳地，防范跨主体调配风险。`

### 0.2 广州拿地线索的表述与评级支柱定位错位【事实定性】
- **问题位置**：
  - **桌面端**广州主体卡片：「现时投入：2024-11以6.03亿元竞得天河金融城东区地块作为未来总部」；右侧 X2 排除项注记：「买地澄清：金融城6亿拿地系广州主体真实投入，非厦门混淆」。
  - **移动端**广州主体卡片：「2024-11以6亿竞得金融城地块」。
- **事实与证据溯源**：
  - 该视觉稿产出时（v3 时点），广州拿地尚在核查期，截图将其写为“真实投入/作为未来总部”属于超前断言。
  - 虽最新核查（analyst v4 引入 E17，天河区政府网原文已核）证实该笔拍卖事实真实存在，但 **v4 裁决与文字报告做出了关键定性收紧**：
    > *拿地属重大资本开支与长期投入信号，对雇员体验影响双向（沉重资产开支可能挤压现金流与薪酬弹性），仅作广州主体连续性的正向参照注记，绝对不作为稳定维度评级支柱，避免在档案中把它呈现为经营稳健的证明。*
- **视觉定性问题**：
  - 截图中将 6.03 亿拿地作为广州主体的高光正面条目凸显，并在 X2 中使用宣扬式口吻（“真实投入”），容易在视觉上给读者造成“该企业实力雄厚、资金稳健无虞”的错误暗示。
- **修订方案（Must Fix）**：
  - 调整文案语气，增加中立性括号注记：
    > `现时投入：2024-11竞得天河金融城东区地块（E17，天河区政府网已核。注：属长期资本开支参照注记，不作为业务稳健评级依据）。`
  - X2 澄清项调整为平实事实陈述，剔除主观定调。

## 一、可读性与文字排版审查（Readability & Typography · P1 级）

### 1.1 案卷元数据文字对比度不足（Contrast Failure）
- **违反规范**：`web-design-guidelines` / WCAG AA 级标准（小文本对比度至少达到 4.5:1）。
- **具体现象**：
  - 桌面端顶部元数据栏：`SHERLOCK-DOSSIER // 09-v3`、`离线侦探档案·商业雇主尽调`、`密级：内部调查样板` 以及 `调查时戳: 2026-09-26 15:35 CST | 来源登记: E1-E16 (v3定点修正)`，采用深蓝灰低饱和色彩（约 `#4a607a`），字号仅约 11px~12px。
  - 在非高亮显示器或暗光环境下，对比度仅为 2.8:1，处于接近不可见的临界点，严重影响专业案卷的时效与版本查验。
- **建议**：
  - 将元数据文本颜色提升至 `#8fa3bf` 或 `#94a3b8`，确保对比度达到 5:1 以上。

### 1.2 移动端正文段落行高紧缩（Line Height Collapse）
- **违反规范**：移动端中文阅读行高应保持在 1.5 ~ 1.7 之间，段间距保持在 0.5em ~ 0.8em。
- **具体现象**：
  - 移动端多处卡片（如主体说明正文、低置信度说明文本、假设对抗卡片描述）行高估算不足 1.3，密集的中文字符上下笔画互相挤迫，在 390px 移动屏上呈现大块“灰黑色块”，产生严重的阅读疲劳。
- **建议**：
  - 移动端正文统一设定 `line-height: 1.6`，字号不低于 `13px`（2x 渲染下为 26px）。

### 1.3 中文排版符号规范与标点倒退
- **具体现象**：
  - 界面中多处滥用自媒体营销号习惯的黑色实心方头括号 `【】`（如 `【求职防坑必读】`、`【求职者实战面试追问清单】`）、英文双斜杠 `//` 泛滥、感叹号过频（`！`）。
- **建议**：
  - 乔布斯式高级版面讲究西文与中文字体的呼吸节奏。建议将方头括号 `【】` 替换为无衬线小字标签（Badge/Tag）或细线大写前缀（如 `RISK NOTE` / `AUDIT NOTE`），去除所有非必要的感叹号，恢复客观中立的案卷口吻。

## 二、信息层级与乔布斯级审美审查（Hierarchy & Taste · P1 级）

### 2.1 警示卡“视觉噪音过载”，破坏评级中立性
- **乔布斯品味批判**：
  > *“Simple can be harder than complex: You have to work hard to get your thinking clean to make it simple.”*
- **具体现象**：
  - 页面顶部第一屏，设计师将 `置信度定级：低 (LOW CONFIDENCE)` 赋予了全屏最高对比度：暗黑底色上铺设大面积深红底色、亮红细边框、红色盾牌叹号图标，并伴随红色加粗文字。
  - 这一“火警消防栓”式的视觉呈现，彻底压制了上方真正最重要的核心评级——`★ 3.5 企业推荐星级`，让读者在看清裁决之前，先被严重的心理恐慌笼罩。
- **设计缺陷分析**：
  - “低置信度”在商业尽调中是指“**公开一手证据缺乏，无法给出高确定性结论**”，属于中立的统计学与证据学限制，并不等于“该公司为极度危险的劣质企业”。设计上的过度报警导致了信息层级的倒错。
- **建议**：
  - 降低警示卡的视觉压迫感。取消整块实心暗红底色，改为冷色调（深灰蓝 `#1e2530`）卡片配以柔和的琥珀橙或灰金色 `LOW CONFIDENCE` 细线徽章（Amber Outline Badge），既严谨标明局限，又不煽动情绪。

### 2.2 桌面端三列网格不平衡，出现严重空间断层（Broken Grid）
- **违反规范**：Bento Grid / 对齐节奏一致性。
- **具体现象**：
  - 桌面端「主体范围与用工防混淆矩阵」由三列组成：左侧厦门总部（7行内容）、中间广州子公司（8行内容）、右侧北京主体（仅4行内容）。
  - 右侧北京主体卡片下方出现了近 160px 的巨大黑色空洞，右下角孤零零挂着一个小小的 X2 排除注记，网格整体下沉，出现严重的失衡感。
  - 底部面试清单区域，右下角「现场勘察技巧」单独占据右半边，左半边留空，造成版面断裂。
- **建议**：
  - 采用不等宽两栏或主次网格重构：厦门（母体）与广州（核心自研）作为主要主体采用 1:1 双栏并列；北京四三九九作为弱关联主体以横向收缩的次级条带（Sub-card）置于底部，消除右侧垂直空洞。

### 2.3 双端语义脱节与证据割裂（Inconsistency）
- **具体现象**：
  - **板块标题不一致**：
    - 桌面端：`主体范围与用工防混淆矩阵 // ENTITY SCOPE & RISK MATRIX`
    - 移动端：`主体划分与防坑提醒 // ENTITIES`（去除了矩阵与风险概念，过于口语化）
    - 桌面端：`证据链账本与可溯源事实 // EVIDENCE LEDGER & AUDIT TRAIL`
    - 移动端：`关键证据账本 // EVIDENCE`
  - **证据删减破坏同源性**：
    - 桌面端完整展示了分类证据与 X1~X6 排除列表；
    - 移动端为了节省高度，直接删除了 X1~X6 排除项展示，且证据仅象征性保留了 4 条。移动端用户无法查看到至关重要的误报排除理由，导致移动端不具备完整的独立自包含性。
- **建议**：
  - 统一双端模块标题与英文子标；
  - 移动端证据账本应采用折叠面板（Accordion）或紧凑型卡片完整呈现所有关键证据索引及排除项，严禁物理截断案卷核心结构。

## 三、移动端溢出与自适应边界审查（Mobile Responsiveness · P2 级）

### 3.1 评级胶囊标签在 390px 边缘紧绷，小屏必折行溢出
- **违反规范**：响应式触控与最小内边距边界（Safe Padding >= 16px）。
- **具体现象**：
  - 移动端「五维深度评级」卡片内部，每一行左侧为维度名称（如“管理风格”），右侧紧跟双值状态标签（如“弱偏负 · 历史创伤”）。
  - 在 390px 标准设计稿下，右侧标签距离卡片内边距已不足 10px。若视口收缩至 375px（如 iPhone SE / 13 mini），或者用户在系统无障碍设置中将字体放大一级，右侧状态标签必定与左侧标题发生文字重叠、强行断行或撑破卡片右边缘！
- **建议**：
  - 移动端重构为垂直堆叠结构：上层为维度标题 + 状态胶囊（Flex Row 左右对齐，留足 20px 间距）；下层独立展示一句话说明文本，彻底解除水平挤压风险。

### 3.2 移动端局部内边距过窄造成的窒息感
- **具体现象**：
  - 移动端顶部免责声明条「⚠️ 一手在职体验证据为0，不能作为入职背书！」卡片左右内边距仅约 8px，单行 32 个汉字几乎顶满屏幕两端；
  - 「⚠️ 签约主体未知警报」框内部文字贴边严重。
- **建议**：
  - 卡片内边距（Padding）严格遵循 8pt 网格系统，容器左右内边距不得小于 `16px`，卡片内 padding 不得小于 `12px`。

### 3.3 链接交互指示缺失（Interactive Affordance）
- **具体现象**：
  - 案卷标明具备“双直链”、“官网可复核”，但在高保真截图中，所有已核直链文字与不可点击的普通描述文字在颜色、下划线及图标上毫无区别，用户无法识别点击目标。
- **建议**：
  - 遵循 `web-design-guidelines`，可跳转的证据链文本应统一添加细微的外链图标（External Link Icon）或淡蓝色细下划线，建立明确的交互心智。
